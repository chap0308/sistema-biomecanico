# Artifact Paths

This file documents the local paths where the project writes analysis artifacts during ingestion, extraction, analysis, reanalysis, and retrieval preparation.

These files are useful for debugging, auditing, and reruns.
Most of them are **not** copied into Supabase or Qdrant directly.

## Main rule

- Supabase stores canonical metadata, drafts, units, and attempt records.
- Qdrant stores only active retrieval-ready vectors and payloads.
- Local artifact files stay on disk unless explicitly promoted to canonical assets later.

## 1. Batch analysis outputs from YouTube runs

Base folder:

- `data/knowledge/video_knowledge_drafts/`

Examples:

- `data/knowledge/video_knowledge_drafts/conorharris_first12_local/`
- `data/knowledge/video_knowledge_drafts/conorharris_newest_31_40_local/`

Typical files per video:

- `NNN_<video_id>_level1.json`
  - Level 1 extracted evidence
  - includes `source`, `assets`, `segments`, and optional `analysis_report`
- `NNN_<video_id>_knowledge_draft.json`
  - second-layer draft from HF or local fallback
- `NNN_<video_id>_sync.json`
  - persistence summary after writing to Supabase and Qdrant

Typical batch summary:

- `run_summary.json`
  - summary of the whole batch

## 2. Direct RAG run artifacts

Base folder:

- `data/knowledge/rag_runs/`

Examples:

- `*_youtube_level1.json`
- `*_youtube_knowledge_draft_hf.json`
- `*_youtube_knowledge_sync.json`
- `ask_rag_*.json`
- `query_rag_segments_*.json`
- `upgrade_drafts_to_gemini_*.json`
- `failed_analysis_attempts.json`
- `retry_failed_analysis_attempts.json`

This folder is the main place for:

- ad hoc experiments
- command outputs
- summaries
- upgrade logs
- failed-attempt listings

## 3. Local processed extraction artifacts

Base folder:

- `data/processed/rag/<source_id>/`

Typical contents:

- `audio.wav`
  - extracted audio from the video
- `transcript.txt`
  - transcript built during Level 1
- `ocr.txt`
  - OCR observations aggregated during Level 1
- `frames/`
  - sampled frames or keyframes used by the pipeline

These are generated by the local fallback extraction path and help explain how a `level1.json` was built.

## 4. Scraping snapshots and state

Base folder:

- `data/knowledge/youtube_channels/`

Typical files:

- `*_scrape.json`
  - snapshot of discovered videos
- `*_pending.json`
  - pending videos after Supabase validation
- `*_scrape_and_analyze.json`
  - scrape + immediate analysis snapshot
- `conorharris_state.json`
  - local seen-state registry for scraping

These files are useful for reproducing discovery and comparing local scrape state against Supabase.

## 5. Gemini upgrade artifacts

When running:

- `scripts/upgrade_drafts_to_gemini.py`

the command creates a folder derived from the output summary path.

Example:

- summary:
  - `data/knowledge/rag_runs/upgrade_drafts_to_gemini_limit5.json`
- per-attempt folder:
  - `data/knowledge/rag_runs/upgrade_drafts_to_gemini_limit5/`

Inside that folder, each attempt may create:

- `<source_id>_<video_id>_gemini_draft.json`
  - raw Gemini draft JSON for that upgrade attempt

These paths are also referenced in:

- `movement_knowledge.rag_analysis_attempts.artifact_paths`

## 6. What is persisted versus what stays local

### Stored in Supabase

- canonical `Source` rows
- canonical `Segment` rows
- valid `KnowledgeDraft` rows
- valid `KnowledgeUnit` rows
- scraping registry
- analysis attempt records
- references to local artifact paths inside `rag_analysis_attempts.artifact_paths`

### Stored in Qdrant

- active evidence vectors in `video_segments_v1`
- active derived knowledge vectors in `video_knowledge_units_v1`

### Kept local only

- raw intermediate JSON outputs
- transcripts in text files
- OCR text files
- audio wav files
- frame images
- most command summaries

## 7. Why we keep these files local first

This makes the pipeline:

- reproducible
- debuggable
- cheaper to iterate on
- easier to audit without inflating Supabase storage

If some artifacts become valuable long-term, they can later be promoted into:

- `rag_assets`
- a bucket
- or another canonical storage flow
